### Task 5: I did NOT implement it the way the directive described

The directive said to read `min_bars_for(bar_seconds)` at the call sites. The
open question it left was *where `bar_seconds` comes from*. I tried deriving it
from `ind.timestamps` first, and **backed it out**. Reason:

Timestamp units are detected by magnitude (`ms` above 1e11). Synthetic series
that start near epoch 0 fall under that bound and read as **seconds**, so a 15m
series built as `i * 900_000` derives a bar size of 900,000 s and C2's
requirement collapses to 3 bars. That turned two existing tests red for a real
reason, not a cosmetic one — a gate that decides NOT_TESTED must not depend on
the caller having used realistic epochs.

Final design keys on the **timeframe label** (`TIMEFRAME_SECONDS`), which is
what `run_sweep` is called with and what the graveyard row is stamped with. It
is deterministic, and it keeps the artifact coherent: a row labelled 15m is
gated as 15m. Unknown label returns `None` (not a guess) and falls back to the
declared `min_bars`, which is the pre-D-274 behaviour; `run_sweep` logs a
warning when that happens so it never looks deliberate.

Wired at all three sites that read `min_bars` (`_scan_start`, `scan_all_bars`,
the `run_sweep` gate). `run_strategy` and `scan_all_bars` derive from the same
label, so they cannot drift — that is the R-005 failure mode and there is a test
pinning it.

Result: sub-hourly C2 is now **NOT_TESTED**, not FAIL.

```
15m: needs 3360 bars at this bar size (class min_bars is 840), max strategy window is 2000
5m:  needs 10080 bars at this bar size (class min_bars is 840), max strategy window is 2000
1h:  unchanged, still genuinely tested
```

The reason string now records the class constant alongside the derived
requirement, so a reader can tell the number was derived rather than mistyped.

Per-clause pass rates at 1.0: `is_upswing` 42.4%, `continuation` 32.1%,
`big_green` 15.1%, `small_reds` 4.3%, **`within_range` 1.03%**. Joint:
`small_reds AND within_range` = **5 bars in 13,901**.

**Diagnosis:** the two conditions now fight each other. `within_range` requires
all three pullback candles strictly inside c1's high/low, while `big_green`
requires c1's range to exceed 1.0 ATR and `small_reds` now *permits* pullbacks
up to 1.0 ATR. A 1.0-ATR candle can only fit inside a barely-larger c1 range
by landing perfectly. Loosening `small_reds` toward the `big_green` floor made
the geometry harder, not easier.

D-278's own text says: "If it still does not fire meaningfully after the
re-sweep, recommend retirement with a D-number." On this corpus it does not fire
at all, and the reason is structural rather than a threshold that needs another
nudge. **Recommend retirement** — but that is Raven's call, and note this is the
daily corpus only, not the full sweep grid.
