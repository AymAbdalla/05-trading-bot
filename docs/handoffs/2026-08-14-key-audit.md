# Key audit: 05-trading-bot public repo

**Date:** 2026-08-14
**Auditor:** Cody
**Requested by:** Raven, authorized by Aym (`docs/handoffs/from-raven/2026-08-14-evidence-pack-and-key-audit.md`)
**Scope:** all 1,327 tracked files (451MB) plus all 1,320 blobs across all 5 commits in every ref
**Repo:** github.com/AymAbdalla/05-trading-bot (PUBLIC)

## Verdict

**PASS. No credential of any kind is exposed in the working tree or anywhere in git history.**

Push is cleared. Three non-blocking hygiene items are listed at the end.

This is an audit, not a scan. The decisive test was not pattern matching: I
loaded the three live secret values out of the real `.env` and searched for
those exact byte strings in every tracked file and in every blob in the object
database. Zero hits. That result does not depend on my regexes being right.

## Non-blocking findings

These do not block the push. Raven and Aym decide what to do.

### F1: `.gitignore` only covers `.env` exactly, not variants (low)

`.env.local`, `.env.production`, `.env.staging` are **not** ignored. Nothing of
that name exists today, so nothing is exposed. It is a foot-gun on a public
repo. Suggested fix, one line:

```
.env*
!.env.example
```

### F2: A 128MB untracked file is not ignored (low, will break a push)

`research/graveyard/archive/v0_graveyard_flatcost_partial_2026-08-13.json`
(128MB) is untracked and does not match the ignore pattern, which only covers
`v0_graveyard_full*.json`. It exceeds GitHub's 100MB hard limit. A careless
`git add -A` would create a commit that cannot be pushed and would need
rewriting to undo. Suggested fix:

```
research/graveyard/archive/*.json
```

This is a size and workflow problem, not a security one. The file contains
backtest results, no credentials (it was swept).

### F3: Telegram chat ID `8017725309` is public (informational)

Appears in the tracked `CLAUDE.md` (lines 31 and 174) and in
`docs/handoffs/2026-08-13-cody-session-1.md` line 6.

This is **not** a credential. A chat ID cannot be used to message Aym without
the bot token, and the bot token is not in the repo. It is a stable personal
identifier on a public repo. Leaving it is defensible; if Aym would rather it
not be public, it should be replaced with a placeholder in both files. Flagging
for his call, not recommending action.

### F4: `.env.example` is missing two variables (informational)

The real `.env` defines `FRED_API_KEY` and `ALPACA_ENDPOINT`. Neither appears in
`.env.example`, so someone cloning the repo will not know they are needed. This
is a completeness gap, the opposite of a leak. Adding empty placeholders would
fix it.

## What was NOT checked

Stating the limits so this is not over-read:

- **Only this repo.** No audit of `~/.hermes/`, `~/.claude/`, or any other
  project on the machine.
- **Only local refs.** The audit covers every blob reachable from every local
  ref. If a commit was ever pushed and then force-removed locally, GitHub may
  still hold the dangling object. Nothing in this history suggests that
  happened (5 linear commits, no rewrites, no dangling objects).
- **No revocation.** This audit does not prove the Alpaca keys were never
  exposed by some other route. D-262 stands: Aym said he will rotate again.
  That is still worth doing, on general principle rather than because of
  anything found here.
- **No GitHub-side check** of forks, PRs, or GitHub Actions logs.

## Method

```
git ls-files                                       # 1,327 tracked files
git rev-list --objects --all                       # 1,360 objects
git cat-file --batch-check                         # filtered to 1,320 blobs
git cat-file blob <sha> | grep -aF -f <secrets>    # per blob, exact value
git grep -a -I -E <pattern> -- .                   # working tree, per pattern
unzip -p <zip> | grep -aE <pattern>                # per zip, 72 archives
git ls-tree -r --name-only <commit>                # per commit, .env presence
git check-ignore -v <path>                         # per path, ignore coverage
```

Probe files under `/tmp` were deleted after use. No secret value was written to
any file or printed to any terminal.
