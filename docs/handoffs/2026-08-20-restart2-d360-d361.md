## 3. Step 2 (D-361 split) is not implementable as briefed - two independent proofs

The brief says: *"remove the fair_value family from main via the reversible D-322
`supported_market_types` override"* and *"add `PM_fair_value_arb`, `_hft`, `_inverse` to
env B's roster."* **Those two instructions contradict each other.**

**Proof 1 - the override is global, not per-book.** `supported_market_types` is a *class
attribute* on the strategy class. Both books load the same classes from the same repo;
they differ only in the `--strategies` roster passed to `shadow_loop`. Setting the D-322
sentinel on the fair_value family removes it from main **and from env B** - emptying the
isolation book of the very thing it exists to isolate.

**Proof 2 - a roster cannot revive a sentinel-killed strategy.**
`filter_strategies_by_name` is applied *after* construction, to the already-routed sets
(its own docstring says so). Routing happens first, via `_supporting()` at
`shadow_loop.py:1527`, which reads `supported_market_types`. A strategy carrying the
`('smart_money',)` sentinel is never routed into any set, so naming it in `--strategies`
matches nothing.

`PM_fair_value_arb_hft` and `PM_fair_value_arb_inverse` **already carry that sentinel**
(D-322, 2026-08-19, Aym's ruling, paused for bleed). So two of the three strategies the
brief adds to env B would be **inert on arrival**. Reproduced directly by the new
launcher's roster gate against the brief's exact 12-name roster:

```

```

exists. Main gets an explicit roster excluding the fair_value family; env B gets one
